## 2. Comprehensive Model-by-Model Parity Matrix

### 2.1. Model 1: `matches`
- **Purpose**: Authoritative catalog of fixtures, kickoff times, scorelines, and match status.
- **Primary Key**: `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- **Unique Constraint**: `canonical_match_id VARCHAR(255) UNIQUE NOT NULL`
- **Kickoff Synchronization**:
  - `kickoff TIMESTAMPTZ` and `kickoff_time TIMESTAMPTZ` kept synchronized via `fn_sync_matches_kickoff()` trigger on `BEFORE INSERT OR UPDATE`.
- **Integrity Columns**:
  - `status VARCHAR(30) NOT NULL DEFAULT 'upcoming'`
  - `data_status VARCHAR(50) NOT NULL DEFAULT 'ACTIVE'`
  - `source_type VARCHAR(50) NOT NULL DEFAULT 'PROVIDER'`
  - `pipeline_metadata JSONB DEFAULT '{}'::jsonb`
- **Row-Level Security (RLS)**:
  - Enabled.
  - `anon` and `authenticated`: Read-only access to published matches.
  - `service_role`: Full CRUD access.

---

### 2.2. Model 2: `market_snapshots`
- **Purpose**: Point-in-time, immutable odds quotes captured from bookmakers (e.g. Pinnacle) prior to match kickoff.
- **Primary Key**: `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- **Foreign Key**: `match_id UUID NOT NULL REFERENCES public.matches(id) ON DELETE RESTRICT`
- **Core Columns**:
  - `market_type VARCHAR(50) NOT NULL` (e.g., `'asian_handicap'`, `'over_under'`)
  - `line_label VARCHAR(50) NOT NULL`
  - `numeric_line NUMERIC(6, 4) NOT NULL`
  - `bookmaker VARCHAR(100) NOT NULL DEFAULT 'pinnacle'`
  - `home_odds NUMERIC(8, 4) NOT NULL`
  - `away_odds NUMERIC(8, 4) NOT NULL`
  - `overround NUMERIC(6, 4)`
  - `source_provider VARCHAR(50) NOT NULL DEFAULT 'PINNACLE'`
  - `captured_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
- **Constraints**:
  - `chk_market_snapshots_odds CHECK (home_odds > 1.0 AND away_odds > 1.0)`
- **Indexes**:
  - `idx_market_snapshots_match_market ON (match_id, market_type)`
  - `idx_market_snapshots_captured_at ON (captured_at)`
- **Immutability Protection**:
  - Trigger `trg_immutable_market_snapshots` executing `fn_prevent_market_snapshot_tampering()`.
  - Prohibits both `UPDATE` and `DELETE` on any existing snapshot row.

---

### 2.3. Model 3: `decisions`
- **Purpose**: Point-in-time evaluation records generated by the quantitative value engine (model probabilities, fair odds, edge, EV, and verdicts).
- **Primary Key**: `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- **Foreign Keys**:
  - `match_id UUID NOT NULL REFERENCES public.matches(id) ON DELETE RESTRICT`
  - `odds_snapshot_id UUID REFERENCES public.market_snapshots(id) ON DELETE RESTRICT`
- **Core Columns**:
  - `market_type VARCHAR(50) NOT NULL`
  - `selection VARCHAR(100) NOT NULL`
  - `line NUMERIC(6, 4) NOT NULL`
  - `badge VARCHAR(20) NOT NULL`
  - `status VARCHAR(50) NOT NULL`
  - `confidence VARCHAR(20) NOT NULL`
  - `confidence_score NUMERIC(5, 2) NOT NULL DEFAULT 0`
  - `model_prob_pct NUMERIC(6, 3) NOT NULL`
  - `implied_prob_pct NUMERIC(6, 3) NOT NULL`
  - `edge_pp NUMERIC(6, 3) NOT NULL`
  - `ev_pct NUMERIC(6, 3) NOT NULL`
  - `sample_size INT NOT NULL DEFAULT 0`
  - `data_quality VARCHAR(20) NOT NULL DEFAULT 'PASS'`
  - `verdict VARCHAR(20) NOT NULL DEFAULT 'LEWATI'`
  - `reason TEXT NOT NULL`
  - `model_version VARCHAR(50) NOT NULL DEFAULT 'dixon-coles-v1.0'`
  - `feature_version VARCHAR(50) NOT NULL DEFAULT 'dynamic-ratings-v1.0'`
- **Constraints**:
  - `chk_decisions_prob CHECK (model_prob_pct >= 0 AND model_prob_pct <= 100)`
- **Immutability Protection**:
  - Trigger `trg_immutable_decisions` executing `fn_prevent_decision_tampering()`.
  - Prohibits both `UPDATE` and `DELETE`.

---

### 2.4. Model 4: `prediction_ledger`
- **Purpose**: The canonical actionable ledger recording official bets, cryptographic hashes, model versioning, and lifecycle states.
- **Primary Key**: `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- **Foreign Keys**:
  - `match_id UUID NOT NULL REFERENCES public.matches(id) ON DELETE RESTRICT`
  - `decision_id UUID REFERENCES public.decisions(id) ON DELETE RESTRICT`
- **Unique Constraint**:
  - `uq_prediction_ledger_doi UNIQUE (doi_id)`
  - Formatted deterministically: `doi_{fixtureId}_{market}_{line}_{selection}_{modelVersion}_{decisionVersion}`
- **Integrity Constraints**:
  - `chk_ledger_prob CHECK (model_probability IS NULL OR (model_probability >= 0.0 AND model_probability <= 1.0))`
  - `chk_ledger_odds CHECK (odds_at_prediction IS NULL OR odds_at_prediction > 1.0)`
  - `chk_ledger_result_status CHECK (result_status IN ('pending', 'WIN', 'HALF_WIN', 'PUSH', 'HALF_LOSS', 'LOSS', 'VOID', 'SETTLED'))`
- **Immutability Protection**:
  - Trigger `trg_immutable_prediction_ledger` executing `fn_protect_prediction_ledger_immutability()`.
  - `DELETE` is unconditionally blocked.
  - `UPDATE` strictly forbids modifying core decision parameters: `doi_id`, `match_id`, `market`, `selection`, `line`, `model_probability`, `fair_odds`, `odds_at_prediction`, `published_at`, `sha256_hash`, `provenance_hash`.
  - Only lifecycle fields (`result_status`, `roi`, `profit_loss`, `settled_at`, `data_status`) can be updated upon match settlement.

---

### 2.5. Model 5: `settlement_results`
- **Purpose**: Append-only audit record of financial settlement outcomes, units won/lost, and scorelines.
- **Primary Key**: `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- **Unique Constraint**:
  - `uq_settlement_ledger_pos UNIQUE (ledger_position_id)`
  - Guarantees position-level granularity so multiple decisions on the same match (e.g. AH -0.25 and AH -0.5) settle independently without collision.
- **Integrity Constraints**:
  - `CHECK (outcome IN ('WIN', 'HALF_WIN', 'PUSH', 'HALF_LOSS', 'LOSS', 'VOID'))`
  - `CHECK (stake_units >= 0)`
- **Immutability Protection**:
  - Trigger `trg_immutable_settlement_results` executing `fn_protect_settlement_results_immutability()`.
  - `DELETE` operations are completely prohibited.

---

### 2.6. Model 6: `daily_picks`
- **Purpose**: Public-facing publishing table serving active, daily qualified picks.
- **Primary Key**: `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- **Unique Constraint**:
  - `uq_daily_picks_prediction UNIQUE (prediction_id)`
- **RLS Configuration**:
  - `anon` and `authenticated`: `SELECT` allowed on `daily_picks` where `status = 'ACTIVE'`.
  - `service_role`: Full access.

---

### 2.7. Model 7: `evidence` & Model 8: `data_provenance`
- **Purpose**: Supporting empirical metrics, cohort win rates, calculation versions, and audit checksums linked to each decision.
- **Foreign Keys**:
  - `decision_id UUID NOT NULL REFERENCES public.decisions(id) ON DELETE RESTRICT`
- **Integrity Checksums**:
  - Non-null SHA-256 verification hashes for data provenance.

## 3. Structural Comparison: Delta Migration vs. Canonical Full DDL

A critical structural finding emerges from comparing `schema_canonical.sql` and `STAGING_MIGRATION.sql`:

| Dimension | `data/schema_canonical.sql` | `docs/epic100g/STAGING_MIGRATION.sql` |
| :--- | :--- | :--- |
| **Creation Context** | Complete ground-up database setup | Delta migration script |
| **Base Table Requirement** | Creates `matches`, `prediction_ledger`, etc., using `CREATE TABLE IF NOT EXISTS` | **Asserts base tables already exist** (Lines 20–32 fail if missing) |
| **Suitability for Fresh Supabase** | **100% Compatible** (can run on completely empty database) | **Incompatible without pre-existing base tables** |
| **Rollback Plan** | Reversible via `data/schema_canonical_rollback.sql` | Reversible via `docs/epic100g/STAGING_ROLLBACK.sql` |

### Architectural Recommendation:
For a fresh staging project, the deployment bundle must either:
1. Execute `data/schema_canonical.sql` directly as the authoritative bootstrap schema; OR
2. Modify `STAGING_MIGRATION.sql` so that it includes the creation of base tables (`matches`, `prediction_ledger`, `settlement_results`, `daily_picks`) if they do not yet exist, rather than aborting.
