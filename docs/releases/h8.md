## 1. Executive Summary

Hotfix H8 (`0b2aa33`) has been audited, hardened, tested (`237/237` tests passing), committed, and deployed to `https://salmo.dev` under strict production containment:
1. **Binary No-Push Per-Leg Brier Scoring (`BINARY_NO_PUSH_PER_LEG`):** Replaced legacy fractional outcome coding (`HALF_WIN = 0.75`, `PUSH = 0.5`, `HALF_LOSS = 0.25`) across [`brierScoring.ts`](../../src/engine/performance/brierScoring.ts), [`performanceMetrics.ts`](../../src/engine/performance/performanceMetrics.ts), [`/api/v1/research`](../../src/app/api/v1/research/route.ts), and [`/api/v1/performance`](../../src/app/api/v1/performance/route.ts). Quarter-lines (`.25`, `.75`) decompose into two `0.5`-stake legs (`[line - 0.25, line + 0.25]`), each scored against its own conditional non-push win probability from the `11x11` Dixon-Coles score grid; push legs (`actualMargin == 0`) are strictly excluded (`binaryOutcome = null`, `brierSqError = null`).
2. **Strict Cohort Separation (`QUALIFIED_PUBLIC_PICKS` vs `MODEL_ALL_ROWS_DIAGNOSTIC`):** Removed the legacy `confidence > 70` fallback from [`isQualifiedPublicPickCohort`](../../src/engine/performance/performanceMetrics.ts). Public qualified picks strictly require `is_pick === true && verdict === 'LAYAK'`, yielding `0` settled and `0` pending picks (`No settled bets`) when `/api/daily-picks` has `0` qualified picks. Diagnostic all-rows metrics (`n = 12` settled EPL rows, `+0.83u`, `+6.92%` flat-stake return) are explicitly labeled `MODEL_ALL_ROWS_DIAGNOSTIC (NOT PUBLIC PICKS)`.
3. **Authoritative Pre-Match Ledger Alignment (Without Mutating Disk Snapshots):** Resolved the 4-fixture (`8`-row) probability discrepancy between `data/verification/live_prediction_ledger.jsonl` (`2026-10-06T21:36Z` pre-match snapshot) and `data/verification/all_leagues_research_ledger.jsonl` (`2026-10-11T18:56Z` multi-league export). Both `/api/v1/research` and `/api/v1/performance` now serve the authoritative `2026-10-06` pre-match probabilities (`18.5%` on Arsenal AH `-1.25`) while exposing `ledgerDiscrepancyAudit` on every `PRODUCTION` row. Neither `.jsonl` file on disk was modified.
4. **15-League Walk-Forward Backtest Recalculation (Read-Only):** Verified strict chronological walk-forward ordering (`max(t_train) < t_eval`, `0` violations across `4,018` evaluated matches in `14` leagues) and proved that the legacy `0.2002–0.2178` balanced quarter-line AH Brier scores were an artifact of fractional outcome coding (`HALF_WIN = 0.75`, `PUSH = 0.5`, `HALF_LOSS = 0.25`). Under binary no-push per-leg scoring, balanced quarter-line AH Brier moves to `0.2406–0.2495`, causing **11 of 14 leagues** to flip from `PASS` (`ci95Upper < 0.2500`) to `FAIL` (`ci95Upper >= 0.2500`).

## 3. Deferred Autopilot & Settlement Defects (`src/engine/settlement/productionSettlementRunner.ts`)

Per Scope Boundaries, automated cron execution remains **disabled** (`"crons": []` in `vercel.json`), and the settlement runner defects in [`productionSettlementRunner.ts`](../../src/engine/settlement/productionSettlementRunner.ts) are documented for the dedicated post-H8 autopilot hardening track:
1. **`dbScoreMap.size === 0` Short-Circuit (Line 135):** `ProductionSettlementRunner.run()` only calls API-Football when `dbScoreMap.size === 0`. Once any single historical match exists in `matches`, new finished matches not yet synced to `matches` are skipped instead of being queried by unsettled fixture IDs/dates.
2. **Hardcoded Date Window (`2026-10-08` to `2026-10-12`, Lines 138–143):** The fallback API-Football loop iterates over a hardcoded 5-day array rather than deriving distinct match dates from unsettled positions' `kickoffUtc`.
3. **EPL-Only League ID (`league=39`, Line 144):** Hardcodes `league=39&season=2026` instead of resolving the league ID per unsettled fixture from `multiLeagueRegistry.ts`.
4. **Fractional Brier Removed (Lines 289–303):** Already remediated in H8 (`30e7021`) using `evaluatePositionBrierLegs`.
