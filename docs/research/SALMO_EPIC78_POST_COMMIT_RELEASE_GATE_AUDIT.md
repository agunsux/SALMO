### 5. Architectural & Runtime Invariants in Ephemeral Environments

SALMO is deployed on Vercel Serverless (AWS Lambda backend). The post-commit audit inspected the behavior of new sync and adapter mechanisms under serverless runtime constraints:

1. **Read-Only Root Filesystem:**
   - Serverless execution environments enforce a read-only root filesystem (`/tmp` is the only writable directory).
   - Canonical historical ledgers (`data/verification/*.jsonl`) are tracked in Git, bundled into the build artifact, and read synchronously via `fs.readFileSync(path.resolve(process.cwd(), ...))`. They persist across cold starts.
2. **Untracked Sync Ledger Resiliency:**
   - `LocalHandicapLabAdapter` looks for `data/sync/handicaplab_sync_ledger.jsonl`.
   - In production or preview deployments where `data/sync/` is absent, the adapter:
     - Catches file-not-found gracefully without crashing or throwing a 500 error.
     - Falls back to `all_leagues_research_ledger.jsonl` or candidate ledgers.
     - Sets response state to `dataState: 'NO_QUALIFIED_PICKS'` or `dataState: 'REAL'`.
     - Zero unhandled exceptions during API route rendering.
3. **Write Protection Guardrail:**
   - `CanonicalPredictionLedger.append()` and `HandicapLabSyncService` explicitly inspect target paths. If a write operation targets any of the 3 protected historical ledger paths, an immediate invariant error is thrown (`Protected historical ledger cannot be mutated`).
